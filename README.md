# architecture-pro-propdevelopment

Проектная работа 5 спринта — кейс PropDevelopment (аудит безопасности архитектуры). Решения по каждому заданию находятся в отдельных директориях, чтобы их можно было проверять независимо.

## Состав сдачи

| Каталог | Артефакты |
| --- | --- |
| `Task1` | Mind map в формате draw.io с классификацией данных и рисками |
| `Task2` | Security checklist в формате Markdown |
| `Task3` | Контекстная и контейнерная C4-диаграммы в формате draw.io, требования к интеграциям с платформой умного дома |
| `Task4` | Описание ролей в `roles.md` и три скрипта для настройки RBAC |
| `Task5` | Kubernetes NetworkPolicy для изоляции трафика между сервисами |
| `Task6` | `analysis.md`, `audit-extract.json` и скрипт фильтрации событий аудита |
| `Task7` | Материалы по PodSecurity Admission и OPA Gatekeeper: insecure- и secure-манифесты, constraint templates, constraints, скрипты проверки, audit policy и README для ревьюера |

## Исходные материалы

При выполнении заданий использованы предоставленные отдельно материалы кейса: описание PropDevelopment, диаграмма контейнеров C4, шаблон проверочного листа и шаблон таблицы ролей RBAC. Сами исходники в этот репозиторий не копируются.

Реальный файл `audit.log` в задании не выдавался. `Task6/audit-extract.json` — синтетический пример с явной меткой `synthetic` в каждой записи: события построены по шагам сценария симуляции инцидента, но не извлечены из настоящего лога и не подтверждают реальный инцидент.

## Проверка перед сдачей

- `bash -n Task4/*.sh Task6/*.sh Task7/verify/*.sh` — синтаксических ошибок нет;
- draw.io файлы (`Task1`, `Task3`) разобраны как XML без ошибок;
- `Task6/audit-extract.json` проверен как JSON, отфильтрован через `Task6/filter-audit.sh` — все ожидаемые события находятся;
- YAML-манифесты `Task5` и `Task7` разобраны без ошибок.

## Ограничения проверки

Kubernetes-манифесты и скрипты (`Task4`, `Task5`, `Task7`) проверены статически — линтеры и синтаксический разбор. Полноценный прогон на живом кластере (`kubectl apply`, runtime-проверка NetworkPolicy, PSA и Gatekeeper) не выполнялся локально из-за отсутствия доступного кластера; ревьюеру нужно прогнать команды из `Task7/README_FOR_REVIEWER.md` и проверки `Task5` на своём кластере.
