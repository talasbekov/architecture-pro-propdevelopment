# PropDevelopment — итоговый проект спринта 5

Репозиторий содержит итоговые материалы по архитектурному кейсу PropDevelopment. Результаты каждого задания находятся в отдельном каталоге, чтобы их можно было проверять независимо.

## Состав сдачи

| Каталог | Артефакты |
| --- | --- |
| `Task1` | Mind map в формате draw.io с классификацией данных и рисками |
| `Task2` | Security checklist в формате Markdown |
| `Task3` | Контекстная и контейнерная C4-диаграммы в формате draw.io, а также требования к интеграциям |
| `Task4` | Описание ролей в `roles.md` и три скрипта для работы с RBAC |
| `Task5` | Kubernetes NetworkPolicy в формате YAML |
| `Task6` | `analysis.md`, `audit-extract.json` и скрипт фильтрации событий аудита |
| `Task7` | Полный набор материалов по PSA и Gatekeeper: insecure- и secure-манифесты, команды или скрипты проверки, audit policy и README для ревьюера |

## Исходные материалы

При выполнении заданий использованы предоставленные отдельно исходники:

- описание кейса PropDevelopment;
- `C4-diagram.png`;
- `PropDevelopment_С4_model.drawio.xml`;
- `IB.md`;
- шаблон RBAC.

Исходники в этот репозиторий не копируются.

Реальный файл `audit.log` не предоставлен. `Task6/audit-extract.json` — синтетический демонстрационный пример с явной меткой `synthetic/demo`: он не извлечён из настоящего `audit.log`, используется только для демонстрации методики и не подтверждает реальный инцидент.

## Проверка

Для итоговой локальной проверки выполнены следующие действия:

- `bash -n Task4/*.sh Task6/*.sh Task7/verify/*.sh` — синтаксических ошибок не обнаружено;
- три draw.io-файла разобраны Python-модулем `xml.etree.ElementTree` без ошибок;
- `Task6/audit-extract.json` проверен как JSON через `jq`: в примере четыре события; дополнительно проверены полный цикл фильтрации и ожидаемый отказ на некорректном JSON;
- через PyYAML разобраны 15 YAML-файлов из `Task5` и `Task7`;
- рендеринг материалов `Task4` сформировал 10 ролей и политик и 7 привязок;
- `git diff --check` завершился без замечаний, итоговый `git status` не содержит незакоммиченных изменений.

## Ограничения проверки

Настроенный Minikube API по адресу `192.168.49.2:8443` недоступен: маршрут до него отсутствует. Поэтому кластерные проверки `kubectl` в режиме dry-run, runtime-матрица NetworkPolicy, PSA, Gatekeeper и готовность secure pod **не выполнялись**. Проведена только статическая и локальная проверка; ревьюеру необходимо запустить команды из `Task7/README.md` и проверки `Task5` в доступном Kubernetes-кластере.
